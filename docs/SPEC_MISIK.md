# SPEC · 회식 메뉴 가챠 (미식)

> 7일차 미식(10_day_07/SPEC_MISIK.md)을 이 프로젝트로 가져온 기획서. 로그인 대신 **자동 로그인**(관리자 계정 하나로 바로 들어감)으로 바꿨다.

## 목표
팀원들이 회식 메뉴를 함께 고르고, 공정하게 뽑고, 기록을 남긴다.

## 인터뷰 질문과 답

| 질문 | 정한 답 | 정한 이유 |
|---|---|---|
| 누가 쓰나? | 화면을 연 사람 누구나 · 자동 로그인(관리자 계정) | 시설 신고함처럼 로그인 화면 없이 바로 씀 |
| 뽑기 방식은? | 등급별 확률 가챠 카드 (R · SR · SSR) | 비싼 메뉴일수록 드물게 |
| 확률은 어디서 정하나? | 등급별 가중치를 DB에 저장 (R 6 · SR 3 · SSR 1) | 코드 수정 없이 조정 |
| 뽑기는 어디서? | 서버에서 뽑음 | 화면(F12)에서 결과 조작 방지 |
| 메뉴 추가 · 삭제는? | 추가 · 삭제 모두 (자동 로그인 계정이 관리자) | 계정이 하나뿐이라 역할 구분 없음 |
| 좋아요 · 싫어요는? | 누를 때마다 +1, 숫자 표시 | 선호를 가볍게 표현 |
| 투표가 확률에 반영되나? | 반영 안 함 | 확률은 등급으로만 단순하게 |
| 뽑기 기록은? | 누가 · 언제 · 무엇을 · 최근 10건 표시 | 같은 메뉴 반복 확인 |

## 사용자
- 자동 로그인 계정 "관리자" 하나: 메뉴를 보고, 추가하고, 투표하고, 뽑고, 삭제한다

## 사용자 스토리
- US-01: 팀원으로서, 메뉴 목록과 각 메뉴의 뽑힐 확률을 보고 싶다. 왜냐하면 무엇이 나올 수 있는지 알아야 하니까.
- US-02: 팀원으로서, 버튼을 눌러 메뉴를 하나 뽑고 싶다. 왜냐하면 고민 없이 공정하게 정하고 싶으니까.
- US-03: 팀원으로서, 먹고 싶은 메뉴를 추가하고 싶다. 왜냐하면 목록에 없는 메뉴도 후보가 되어야 하니까.
- US-04: 팀원으로서, 메뉴마다 좋아요 · 싫어요를 누르고 싶다. 왜냐하면 팀의 선호를 함께 보고 싶으니까.
- US-05: 팀원으로서, 최근에 뽑힌 메뉴를 보고 싶다. 왜냐하면 지난번과 같은 메뉴인지 알고 싶으니까.
- US-06: 팀원으로서, 메뉴를 삭제하고 싶다. 왜냐하면 문 닫은 가게나 장난 메뉴를 정리해야 하니까.

## 인수 기준 (Given / When / Then)

### AC-01 메뉴 목록과 확률 (US-01)
- Given: 시드 메뉴 100개(R 60 · SR 30 · SSR 10)가 있을 때
- When: 미식 화면(`/misik/`)을 열면
- Then: 메뉴마다 이름 · 등급 배지 · 뽑힐 확률(%) · 좋아요 수 · 싫어요 수가 보이고, 확률의 합은 100%

### AC-02 뽑기 (US-02)
- Given: 메뉴가 1개 이상일 때
- When: [뽑기]를 누르고 카드를 누르면
- Then: 서버가 등급 가중치대로 뽑은 메뉴가 카드 앞면에 나오고 "오늘의 회식은 ○○!"가 보임 · 메뉴가 0개면 뽑기 버튼이 꺼짐

### AC-03 메뉴 추가 (US-03)
- Given: 메뉴 추가 칸에서
- When: 이름(1~30자)과 등급을 넣고 [추가]를 누르면
- Then: 목록에 추가되고 확률이 다시 계산됨 · 이미 있는 이름이면 "이미 있는 메뉴입니다" · 빈 이름이면 "메뉴 이름을 입력하세요"

### AC-04 좋아요 · 싫어요 (US-04)
- Given: 메뉴 목록에서
- When: 👍 또는 👎를 누르면
- Then: 그 메뉴의 해당 숫자만 1 올라가고, 새로고침해도 유지됨

### AC-05 최근 뽑기 (US-05 · Should)
- Given: 누군가 뽑기를 했을 때
- When: 미식 화면을 보면
- Then: 최근 10건이 최신순으로 메뉴 · 등급 · 뽑은 사람 · 시간과 함께 보임

### AC-06 메뉴 삭제 (US-06)
- Given: 메뉴 목록에서
- When: 메뉴의 [×]를 누르면
- Then: 목록에서 사라지고 확률이 다시 계산됨 · 없는 메뉴를 지우려 하면 404

### AC-07 자동 로그인 (공통)
- Given: 아무 준비 없이
- When: 미식 화면(`/misik/`)을 열면
- Then: 로그인 폼 없이 바로 쓸 수 있고, 위쪽에 "관리자"가 보이며, 뽑기 기록의 뽑은 사람도 "관리자"

### AC-08 AI 추천 (8일차 · Claude API)
- Given: 메뉴 목록에서
- When: 조건 칸에 "갑각류 알레르기 있음, 해장하고 싶음"처럼 쓰고 [AI 추천]을 누르면
- Then: AI가 조건에 맞는 메뉴를 추천하고, 화면은 추천 메뉴를 이유와 함께 보여 줌 · 추천 외 메뉴는 목록에서 취소선 · 확률은 추천 메뉴로 다시 계산 · [뽑기]는 추천 메뉴 중에서만 뽑음 · [조건 지우기]를 누르면 처음대로
- 규칙: AI는 **남길 메뉴 추천만** 하고 뽑기는 서버의 등급 가중치 추첨 그대로 · AI 답은 서버가 검사해서 목록에 있는 메뉴 번호만 씀 · 조건은 1~200자 (아니면 400)
- AI가 멈추면(키 없음 · 네트워크 · 시간 초과 60초) 503 `AI_UNAVAILABLE` "AI가 지금 응답하지 않습니다. 조건 없이 뽑아 주세요" · 뽑기는 그대로 됨
- 추천이 0개(또는 남은 메뉴가 0개)면 뽑기 409

## MoSCoW
- Must: AC-01 · AC-02 · AC-03 · AC-04 · AC-06 · AC-07 · AC-08
- Should: AC-05
- Could: 화면에서 등급 확률 수정 · 투표를 확률에 반영

## 기술 결정 (PLAN 성격)
- 시설 신고함과 같은 서버(`src/server.js`) · DB 창구(`src/db.js`, supabase · sqlite · memory)
- 주소: 화면 `/misik/` · API `/api/me` · `/api/grades` · `/api/menus` · `/api/menus/:id`(DELETE) · `/api/menus/:id/vote` · `/api/draws`(POST에 `only`: 뽑을 후보(추천) 번호 배열, 생략하면 전체) · `/api/menus/filter`(POST `condition` → `{ recommended: [{ id, name, reason }] }`). `exclude`를 `only`로 바꾼 이유: 추천 뒤 새로 추가한 메뉴가 뽑기에 끼지 않게 화면이 "뽑을 후보"를 보냄
- AI: Claude API(`claude-opus-5-5`)를 `src/ai.js` 한 곳에서 fetch로 부름 · 키는 `.env`의 `ANTHROPIC_API_KEY` · 답 모양은 구조화 출력(JSON 스키마)으로 고정
- DB: `misik_grades` · `misik_menus` · `misik_votes` · `misik_draws` (`src/migrations/*/002_misik.sql`) · 시드는 `data/misik_seed.json`
- 실패 응답 모양은 SPEC.md 5절과 같음 · 이미 있는 메뉴 · 메뉴 없이 뽑기는 409 `CONFLICT` · 테스트는 `tests/misik.test.js`
- 화면은 React 없이 HTML 한 장(`src/public/misik/index.html`) · 7일차 양피지 디자인 그대로 · 글꼴 Galmuri11(`src/public/fonts/`, OFL)
