# 현장 제보 카드 (기준이 미리 써 있음)

시범 운영 첫 주, 총무팀에 쌓인 제보다. `npm test`는 8개 모두 초록불인데 현장은 다르다.
각 제보에는 **합격 기준(Given / When / Then)이 이미 써 있다.** 이번 실습에서는 기준을 새로 쓰지 않고, 읽고 이해한 뒤 이 기준으로 AI에게 맡긴다.

## 기준 읽는 법
- Given: 이미 어떤 상태인가
- When: 무엇을 신청하는가
- Then: 화면에서 확인되는 결과 (상태 번호, 오류 이름, 목록에 남는지)
- 기존 기준 AC-1~AC-8은 `SPEC.md`에 있고, 이 카드의 기준은 AC-9부터 이어진다

## 한눈에
| 번호 | 제보 | 기준 요약 |
|---|---|---|
| AC-9 | FB-1 사고 | 앞쪽이 걸치는 신청은 409 |
| AC-10 | FB-1 사고 | 기간 전체를 덮는 신청은 409 |
| AC-11 | FB-2 | 반납한 건과 겹쳐도 신청 가능 (201) |
| AC-12 | FB-3 | 7일 신청은 가능 (201) |
| AC-13 | FB-3 | 8일 신청은 거절 (400) |

---

## FB-1 사고: 같은 노트북에 두 사람이 마주침
> "NB-01을 12/10~12/12에 빌린 분이 있는데, 12/8~12/10으로 또 승인돼서 두 사람이 같은 날 노트북을 찾으러 왔어요."

**AC-9 앞쪽이 걸치는 신청**
| | |
|---|---|
| Given | NB-01이 12/10~12/12에 대여 중 (김대리) |
| When | NB-01을 12/8~12/10으로 신청 |
| Then | 409로 거절, 대여 목록은 그대로 |

**AC-10 기간 전체를 덮는 신청**
| | |
|---|---|
| Given | NB-01이 12/10~12/12에 대여 중 (김대리) |
| When | NB-01을 12/9~12/14로 신청 |
| Then | 409로 거절, 대여 목록은 그대로 |

## FB-2 반납했는데 다시 못 빌림
> "NB-02를 12/1~12/5로 빌렸다가 12/2에 일찍 반납했어요. 그런데 12/3~12/4에 다른 팀이 빌리려니 거절돼요."

**AC-11 반납한 건과 겹치는 신청**
| | |
|---|---|
| Given | NB-02가 12/1~12/5로 대여됐고 이미 반납됨 (status: returned) |
| When | NB-02를 12/3~12/4로 신청 |
| Then | 201로 승인, 대여 목록에 추가 |

## FB-3 한 달째 안 돌려주는 사람
> "모니터를 한 번에 한 달씩 빌려 가는 분이 있어요. 한 번에 빌릴 수 있는 기간 상한이 필요해요."

- 기획 결정: 한 번에 빌릴 수 있는 기간은 **최대 7일** (시작일과 종료일을 모두 포함해서 센다)

**AC-12 7일 신청**
| | |
|---|---|
| Given | 대여 중인 건 없음 |
| When | MON-01을 12/1~12/7로 신청 (7일) |
| Then | 201로 승인 |

**AC-13 8일 신청**
| | |
|---|---|
| Given | 대여 중인 건 없음 |
| When | MON-01을 12/1~12/8로 신청 (8일) |
| Then | 400으로 거절, 대여 목록은 그대로 |

---

## 읽고 생각해 볼 것
- 기준마다 Then이 숫자나 말로 확인되는가
- 7일은 되고 8일은 안 된다는 경계가 분명히 쓰였는가
- 이 기준들이 **말하지 않은 것**은 무엇일까? (다른 눈 단계에서 다시 만남)
